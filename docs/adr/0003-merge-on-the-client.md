# 在客户端执行三方树合并

服务端只校验对象并以强 ETag 原子发布 Head；客户端基于 Sync Base、Local Candidate 和 Remote Head 递归合并目录树。这样服务端并发语义保持为小而确定的 CAS，并允许客户端在 checkout 前保留本地冲突内容；代价是每个平台客户端都必须通过相同状态机、连续 CAS 冲突和崩溃恢复测试。

考虑过沿用 Seafile 的服务端合并。它会把路径、冲突命名和版本生成策略放入服务端，并使 WebDAV 与原生客户端更容易产生不同结果。只有出现不可信客户端无法安全生成合并 Commit，或多个客户端实现无法保持测试向量一致时重新评估。
