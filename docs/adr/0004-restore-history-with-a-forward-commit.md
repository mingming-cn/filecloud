# 通过前向提交恢复历史内容

历史恢复从已发布提交取回选定路径，叠加到当前 Head，并通过正常对象上传和 Head CAS 发布一个新的单 parent 提交；不把 Head 强制指回旧提交，也不只在本地工作目录临时 checkout。这样当前版本、恢复来源和恢复结果始终可达，并让并发控制、结果未知恢复和跨平台 checkout 继续复用唯一的同步发布状态机；代价是恢复前必须确认工作目录已经收敛，预览后的 Head 或工作目录变化会使恢复候选失效。

考虑过直接回退 Head、只恢复到本地以及由服务端构造恢复提交。直接回退会绕过前向 CAS 历史并影响其他设备；只恢复到本地会把恢复意图混入下一次普通同步；服务端构造会形成第二套树变换和发布路径，因此否决。
